# 远程交互模式（agent-ntfy）：用户离席时，要拍板的事推到手机

> 这是一份**给 agent 读的常驻规则示例**。skill 本身只提供通路（`ask` / `notify` / `away`），不规定什么时候用；
> 什么时候用由这样一条规则定。Claude Code 用户把本文件复制到 `~/.claude/rules/`（每个会话自动注入）即可；
> 其他 agent 放到它常驻加载的位置。英文版见 `remote-mode-rule.md`。
>
> 下文 `$AN` = `python3 <skill dir>/scripts/agent_ntfy.py`；Claude Code 全局安装时 `<skill dir>` 是 `~/.claude/skills/agent-ntfy`。怎么写一张提问卡看 SKILL.md。

## 状态在哪：`<项目根>/.agent-ntfy/state.json`（CLI 写，你只读）
- **会话开始 / 上下文被清空或重置后**，先 `$AN away status --json`：`away: true` ⇒ 本项目已在远程模式，照「模式内」办；文件不存在或 `false` ⇒ 正常终端交互。
- 字段：`away`（开关）· `slot`（本项目当前租的槽位，`null` = 还没租）· `confirmed`（那个槽位过没过闸）· `target`（谁写的）。**里面永远没有 topic 名。**

## 开 / 关（用户的话就是开关）
- **开启**：「开启远程交互模式」「我走了，有事发手机」「切到手机」「remote on」。用户此刻还在键盘旁，**当场做三件**（离席后手机上那两下没人做）：
  1. **从自己的终端窗格**跑 `$AN away on`（一站式：daemon 没跑就起——herdr 内开窗格起、否则后台 detach；确保有已过闸的槽位；然后才写开关），**stdout 原样转告用户**。三种结果：「已开启，槽位 slotN 就绪」⇒ 完成（槽位当场租下）；「slotN 还没过闸：已在 herdr 窗格 <id> 里开始确认，请转告用户 1. 2. 3.」⇒ 让用户看那个窗格订阅 topic、按回车、手机通知栏点按钮（topic 只显示在那个窗格，不进你的会话；结束时你的会话会收到一行 `[agent-ntfy] slotN 已过闸 / 确认超时 / 被中断`——系统事件，不是用户说的，按它办，不必轮询 `slots`）；「正在确认中（已有窗格）」⇒ 让用户去那个窗格完成；rc 3 / 4 ⇒ **没开启**，按 stderr 办（herdr 外且未过闸 ⇒ 用户自己在终端跑 `$AN confirm-sub <slot>`；租满 ⇒ 把 stderr 里的占用情况转告用户，由他决定：自己去某个项目关远程模式，还是让你 `$AN add-slot` 后再 `away on`；**不要替别的项目 `release`**，daemon 也会拒）。
  2. `$AN away status --json` 核 `away: true`（它顺带登记注入目标窗格，**只在自己的窗格跑**）；过闸是异步的，用户点完按钮再看一次 `confirmed`。
  3. 回一句 stdout 的结论。
- **关闭**：「关闭远程交互模式」「我回来了」「remote off」⇒ 走「关闭与收尾」。

## 模式内
- **一切本来要向用户提问、要他确认或授权的时刻** ⇒ 用 `$AN ask`，不再在终端等。
- `ask` 会阻塞到用户回答。你的 shell 工具有执行时限的话（Claude Code 的 Bash 工具是 10 分钟），**放后台跑并把 stdout / stderr 重定向到文件**——前台被杀 daemon 会视为取消、卡片作废；收到完成通知再读文件取回复与退出码。**同一时刻只挂一个 `ask`**（同槽位第二个退 4）。
- 退出码：0 按回复办；1 改 JSON 重发；2 超时 ⇒ 可逆的事按推荐项继续并记「未获确认」，不可逆的停下等人；3 通道故障 ⇒ 起 daemon 重发一次，仍 3 停下；4 需要人（未过闸 / 租满 / 忙）⇒ 停下等用户回终端。
- **手机来的消息以 `[agent-ntfy remote] ` 前缀注入你的会话**（**只在 herdr 内**；herdr 外没有注入，他主动发的消息只会收到「没有登记目标窗格」的回执，`ask` 的回复照常回到调用），按用户输入处理；他随后发的任何消息一律先当挂着的提问的回复。
- **`$AN notify`（单向通知：stdin JSON `{title, body, lang}`，不阻塞、无按钮，提问挂着时也能发）只在两种情况下用**：① 用户从手机问了只要回话的问题（「进展如何」）——回答放 body；② **重大事项、必须让用户知道而不需要他拍板**：任务完成 / 发生异常错误 / 任务无法继续（含 `ask` 退 3、4 后停下等人）。其余进展、中间结果、顺带一提**一律不发**——每条都会响手机，ntfy.sh 配额 250 条/天/IP。要拍板的事永远走 `ask`，不用 notify 代替。
- 远程模式只换通道，**不降标准**：不可逆动作仍要明确批准，超时不算批准。
- 一张卡渲染后上限 3584 字节：长 commit message **一笔一卡**，别合并；超了 CLI 会拦下不发（rc 1），改 JSON 重发。
- 需要用户验证某个改动（版式 / 文案）时不单发验证卡——塞进下一张本来就要发的真问题卡（「这张卡顺便看 X」），省配额。
- 用户在终端直接回话（没有 `[agent-ntfy remote] ` 前缀）而手机上还挂着一张 `ask` ⇒ 先停掉那个后台任务（Claude Code 里是 TaskStop；卡片会变「已取消」），再按终端回话办；不要两边都等。

## 多个 agent 会话组队时（一个主会话派活给别的会话）
- **只有对接用户的那个会话（主会话）持有远程模式**：租槽位、发 `ask` / `notify`、读 `state.json`。其他会话照旧只对接主会话，不租槽位、不调 `ask`。
- 别的会话需要用户授权 / 拍板的事 ⇒ 由主会话用 `ask` 问用户，拿到答复后按你们既有的通道转达。
- 手机来的消息注入的是主会话（租约里记的窗格），带 `[agent-ntfy remote] ` 前缀 ⇒ 当用户输入。
- 状态以 `state.json` 为准，主会话重置后照第一节重读即可；队伍自己的状态文件里写一句「远程模式见 state.json」就够，别另记一份。
- 你们若有「自动驾驶 / 不必逐项请示」之类的授权，它与远程模式正交：前者管哪些事不必问，后者管必须问的走哪条通道。

## 关闭与收尾（缺一步都不报错）
- 关闭模式：先确认没有挂着的后台 `ask`（有 ⇒ 等它或停掉，卡片会变「已取消」）→ `$AN away off`（顺带释放本项目的槽位、清文件里的 `slot`；daemon 留着不停）。
- 任务收尾同样 `release`；模式仍开着就留着开关（用户没回来）。
- 手机上的订阅 / 退订 / 点按钮是用户的动作，agent 不代做、也做不了。

## 禁止
- topic 名是密码：不写进任何文件、报告、消息（看 topic 只有 `$AN confirm-sub <slot> --show-topic`，在用户自己的终端跑）。
- 不用自己的后台 shell 去起 daemon 常驻（用 `--detach`，或 herdr 里另开窗格）；不手改 `state.json`，只经 `away` / `ask` / `release`。
